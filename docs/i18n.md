# 中英双语（i18n）

界面支持中文与英文，**默认跟随浏览器语言**（`Accept-Language` 里 `zh*` 就是中文，其余英文），
用户在「设置 → 外观 → 语言」里手动选过之后记在 `localStorage` 的 `pinboard-locale`。

## 为什么是「中文原文当 key」

字典是 `中文原文 → 英文译文` 的扁平映射，源码里直接写 `t('保存')`，不起 `save_button` 这种 key：

- **缺条目自动回落中文原文**，不会报错、不会显示 key。翻译可以按页慢慢补，界面永远可用。
- 改文案只改一处（源码里的中文），不用同步改 key。
- 代价是中文原文必须是稳定的「一句完整文案」，别把变量拼进去（用占位符，见下）。

## 前端

```tsx
import { t } from '../lib/i18n'

t('保存')                                  // → Save
t('{n} 条便签', { n: 3 })                   // → 3 notes（英文用函数条目做复数）
```

- `t()` 是**普通函数**，不是 hook：纯函数、模块级常量、事件回调、`confirm()` 里都能用。
- **切语言靠 `useLocale()`**：它在 `web/App.tsx` 根部订阅一次，切语言时整棵树重渲染。
  所以**以后谁用 `React.memo` 包组件，那个组件就必须自己再调一次 `useLocale()`**——
  父组件重渲染会被 memo 挡住，文案就不会跟着变。目前 `web/` 里没有一处 `React.memo`
  （`grep -rn 'memo(' web/` 为空），这条是预防性的；`BeatStrip`、`Lightbox` 已经提前各订阅了一次，重复订阅是无害的空操作。
- **不要在模块常量里调 `t()`**：那会在 import 时把当时语言的译文冻住。
  常量里存中文原文，渲染时再过 `t()`（见 `web/pages/settings/AppearanceCard.tsx` 的 `THEMES`）。
- **局部变量别叫 `t`**：`const t = setTimeout(...)`、`tags.map((t) => ...)` 会把翻译函数遮住。
  改成 `timer` / `tg` 之类的名字。
- 日期/数字格式化用 `localeTag()`（`zh-CN` / `en`），别写死 `'zh-CN'`。

## 占位符与复数

中文原文里可以有 `{name}` 占位符，译文用同名的：

```ts
t('已过期 {n} 天', { n: 3 })   // zh: 已过期 3 天   en: expired 3 days ago
```

英文有单复数时，字典条目写成函数：

```ts
'{n} 条便签': (v) => `${v.n} ${Number(v.n) === 1 ? 'note' : 'notes'}`,
```

## 服务端

服务端的文案（接口错误、快照里的句子）也要跟着**发起请求的客户端**变：

- `server/index.ts` 在鉴权中间件之前挂了 `withLocale(pickLocale(Accept-Language))`，
  用 `AsyncLocalStorage` 把语言放进请求作用域。
- 路由里照旧写 `import { t } from '../i18n.js'`，然后 `t('不能删除有部署的服务')`——
  不用把 locale 一路传下去。
- 前端 `web/lib/api/http.ts` 每个请求都带 `Accept-Language: localeTag()`，
  登录页的裸 `fetch` 也手动带了这个头。

## 字典文件

`shared/i18n/en/` 下按区域拆文件，`index.ts` 统一合并，**同名键后面的覆盖前面的**
（所以页面文件排在 `common.ts` 后面，可以按页微调公共词的语气）：

| 文件 | 覆盖范围 |
|---|---|
| `common.ts` | 保存 / 取消 / 删除 / 名称 / 颜色 … 各页共用的词 |
| `format.ts` | 相对时间、到期、资产类型与状态 |
| `shell.ts` | 侧栏、顶栏、命令面板、异常通知、页面标题 |
| `auth.ts` | 登录 / 首次设密码 |
| `notes.ts` `assets.ts` `monitors.ts` `hosts.ts` `services.ts` `mail.ts` `backup.ts` `settings.ts` | 各页 |
| `server-monitor.ts` | 服务端：观测（kuma）与主机指标 |
| `server-core.ts` | 服务端：其余路由 |

同一个中文原文只该有一份译文；`common.ts` 里已有的词，页面文件不要再定义。

## 巡检脚本

```bash
node tools/i18n-scan.mjs            # 列出还没包 t() 的中文（文件:行 + 片段）
node tools/i18n-scan.mjs --files    # 按文件汇总，排工期用
node tools/i18n-scan.mjs --missing  # 源码里有、字典里缺的条目（去重）
node tools/i18n-scan.mjs --check    # 还有未包装的中文就 exit 1
```

脚本不做完整 AST，用字符状态机区分「字符串 / 注释 / 裸文本」，够用：
字符串里出现 CJK 且紧邻前面不是 `t(` → 待翻译；字符串之外出现 CJK（JSX 文本）→ 待翻译；注释忽略；
**`console.log/warn/error/…` 的参数忽略**（日志是给运维看的中文，见下面的「已知边界」）。

脚本里有一张 `KNOWN_TODO` 表，按文件给上限（7 个文件共 13 处：写进 Kuma 的观测项名字、`STEP_LABEL` 常量值、
正则里带引号造成的误报、FRPC 模板、心跳状态前缀）。这些是数据 / 协议常量 / 误报，本来就不该翻，`--check` 不算它们，
所以**可以进 CI**；往这些文件里新加未包装的中文会让计数超上限，照样 exit 1。

判「是不是 t() 包住」用的是**紧邻下标**：字面量正文第一个字符的下标往前退两位（跳过开引号），
再跳过空白找 `(`。这个下标算错过一次（退一位落到了引号上，导致所有 `t('…')` 都被判成未包装），改的时候盯住。

## 已知边界（故意不翻）

- `server/snapshot/markdown.ts` 生成的 `SNAPSHOT.md` 是**仓库文档**，不随界面语言变（已加进扫描器的 skip 列表）。
- 数据本身（便签正文、标签名、资产名、服务器名、服务名、观测项名）不翻，只有界面文案翻。
- **IMAP 信箱名原样显示**：`草稿` / `垃圾邮件` / `已发送` 这些是邮箱服务器给的名字，不是本项目的文案，切英文后仍是中文（Gmail 用英文账号时就是英文）。
  需要的话只能按 RFC 6154 的特殊用途标记映射，不在本次范围。
- **日志不翻**：`console.log/warn/error` 里的话是给运维（就是你自己）看的中文，
  SQL、迁移、内部断言、代码注释同理。扫描器已经忽略 `console.*` 的参数。
- 服务端返回的文案跟着请求的 `Accept-Language`；用 `curl` 直接调 API 时没这个头 → 中文。
- 服务端相对 import **一律带 `.js` 后缀**（`import { t } from '../i18n.js'`），
  这是本仓库 `server/` 下 191 处 import 的统一风格，别写成 `'../i18n'`。

## 测试

**单测**（`tests/unit/i18n-core.test.mts`）测两件事：

- `core.ts` 的纯函数：`interpolate` / `translate` / `pickLocale`（含中文永远回落源码原文、q 值排序、坏 q 值）。
- **英文字典的完整性**：没有空键空译文、字符串条目的 `{占位符}` 必须和中文原文一致、函数条目缺 vars 也不抛错。
  并行翻译最容易犯的就是 `{n}` 写成 `{count}`——界面上只会安静地少一个数字，不报错。

**e2e**（`tests/e2e-i18n.mjs`，已进 `core` 套件）：

- `tests/login.mjs` 默认在 `addInitScript` 里把 `pinboard-locale` 钉成 `zh`
  （Playwright 默认 `en-US`，不钉的话所有中文断言都会挂）。**它每次导航都会重写 localStorage**，
  所以测语言切换的用例必须传 `login(page, B, { pin: false })`，改用 `newContext({ locale: 'zh-CN' })` 让首次访问自然落在中文。
- 用例走真实用户路径：设置页点 `English` → 侧栏 / 标题 / 占位符 / `<html lang>` 全变英文 → **刷新后仍然是英文** →
  再点回中文全变回来。另外用 `page.evaluate` 带 `Accept-Language` 调同一个 404 接口，
  验服务端中英两边都能给出对应语言的报错。
