## 1. 背景与要解决的问题

用户手上有多个邮箱（已知：**Gmail、QQ 邮箱、163 邮箱**，后续可能更多），当前痛点是：

1. 每看一次邮件要分别打开 Gmail、QQ 邮箱、163 邮箱三个网页，来回切换，费时。
2. 已经试过自建 Cypht（曾部署在 azfree，`https://203.0.113.10/mail/`，**该服务已于 2026-10-21 按用户要求整体拆除**），结论是**不可用**：
   - 页面太重、功能太多（日历、联系人、RSS、Sieve、多协议），用户只用「收信 + 看信」；
   - 访问慢（跨境链路 + 大前端），体验不可接受；
   - 用户原话：「还是很麻烦，等很久，而且页面太复杂了，我只有接收邮件，看邮件的需求，其他的我都不需要」。

**因此本需求的核心不是「做一个 webmail」，而是「把多个邮箱的收件箱合成一个轻量列表，点开就能看」。**

## 2. 目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 一个页面看到所有邮箱的来信 | 打开 `/mail` 即见合并后的邮件列表，无需逐个切换 |
| G2 | 点开就能读，不跳转、不等 | 从点击到正文可读 ≤ 1 秒（缓存命中时 ≤ 300ms） |
| G3 | 极简：只有收信和看信 | 页面上不出现发信、日历、联系人、RSS 等入口 |
| G4 | 就在pinfolio里，本机访问 | 与便签/资产/观测同一套界面与端口（`http://127.0.0.1:7788/mail`） |
| G5 | 多账号可增删，不写死 | 页面内可添加/编辑/删除邮箱账号，支持任意 IMAP 邮箱 |

## 3. 非目标（明确不做）

- ❌ 发信 / 回复 / 转发 / 草稿
- ❌ 删除、移动、归档、标记垃圾邮件（**不修改服务器上的邮件**）
- ❌ 日历、联系人、RSS、Sieve 过滤器、JMAP/EWS 协议
- ❌ 多用户 / 登录鉴权 / 公网暴露（沿用现状：仅本机 127.0.0.1，无鉴权）
- ❌ 移动端专门适配（能看即可，不做 App）
- ❌ 邮件推送通知（P2 再议，见 11 章）

## 4. 用户与场景

**用户**：本人，单机单用户，本机浏览器访问。

**核心场景（按发生频率排序）**

1. **扫一眼有没有新邮件**：打开 `/mail`，看合并列表，未读高亮，几秒内判断有没有要处理的。
2. **读一封具体的邮件**：点列表某一封 → 右侧直接出正文 → 看完继续看下一封。
3. **只关心某个邮箱**：点顶部账号筛选（如「QQ」），只看该账号的来信。
4. **加一个新邮箱**：在页面里填 IMAP 地址、账号、授权码 → 试连通过 → 保存，立刻出现在列表里。
5. **某天某个邮箱连不上**：其他邮箱照常显示，出问题的那一行明确提示原因，不整页报错。

## 5. 功能需求

优先级：**P0 = 必须有（否则不可用）**，**P1 = 应该有**，**P2 = 以后再说**。

### 5.2 邮件列表

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-7 | **统一收件箱**：所有启用账号的收件箱邮件合并为一个列表，按收信时间倒序 | P0 | 不同账号的邮件交错按时间排列 |
| FR-8 | 列表行显示：发件人名称、邮件标题、摘要（前 1~2 行纯文本）、时间、所属账号标记 | P0 | 一行能看出是谁发的、说什么、哪个邮箱 |
| FR-9 | 未读邮件视觉区分（加粗/圆点），已读变常规字重 | P0 | 一眼分辨未读 |
| FR-10 | 按账号筛选（chips：全部 / Gmail / QQ / 163 …） | P0 | 点 chip 只显示该账号 |
| FR-11 | 每账号默认拉取最近 50 封，但**必须能一直加载到最早一封**（滚动到底或点「加载更多」，每页 50）；即：账号里的邮件**全量可浏览**，只是分批拉，不一次性拉完 | P0 | 拿真实 Gmail 账号验证：能翻到最早的邮件，不卡死、不重复、不丢 |

| FR-13 | 搜索：在当前已加载邮件里按发件人/标题/摘要过滤 | P1 | 输入即筛（防抖） |
| FR-14 | 按文件夹查看：收件箱（默认）/ 其他文件夹（至少能选到垃圾箱、已发送，只读） | P1 | — |
| FR-15 | 未读数角标：顶部账号 chips 上显示未读数。**数据来自服务器 FLAGS（UNSEEN），只在本页主动刷新或自动轮询时更新**——因为本页从不改已读状态，未读数不会因阅读而减少 | P1 | 与原邮箱网页版未读数一致 |

| FR-20 | **远程图片默认加载**（D4，2026-10-21 用户改主意）；阅读区提供「隐藏图片」开关，隐藏后顶部提示「已拦截 N 张外部图片」+ 一键恢复。选择记在本机（localStorage） | P0 | 打开即见完整排版；点「隐藏图片」后不再请求外链；**无论显示与否都不改服务器已读状态** |

## 6. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-1 | 性能 | 列表首屏 ≤ 2s（三账号各 50 封）；缓存命中 ≤ 300ms；正文 ≤ 1.5s |
| NFR-2 | 轻量 | 不引入新服务、不需要 Docker、不需要数据库服务；随pinfolio同一进程启动 |
| NFR-3 | 数据本地 | 凭据与缓存只在本机；不发往任何第三方 |
| NFR-4 | 凭据存储 | 存本机 SQLite，明文或简单混淆；页面接口不回传密码（见 Q3） |
| NFR-5 | 只读安全 | 服务端只实现读操作（`ID` / `LOGIN` / `SELECT` / `SEARCH` / `FETCH`），**一行 STORE 都不许有**；服务器上的邮件状态（已读、星标、所在文件夹）一律不改动，保证「本工具看过的邮件在原邮箱仍是未读」 |
| NFR-6 | 容错 | 单个账号连不上/超时（默认 20s）不影响其他账号；列表里标注该账号「连接失败：原因」 |
| NFR-7 | 兼容 | 必须支持 Gmail（应用专用密码）、QQ 邮箱（授权码）、163 邮箱（授权码）；163 需在登录后发送 IMAP ID 命令才能打开收件箱 |
| NFR-8 | 界面一致性 | 沿用pinfolio现有暖纸色设计（`--paper #f6f3ec` / `--accent #b45309`）、深色模式、侧栏导航 |
| NFR-9 | 路由 | 页面地址 `/mail`，刷新/深链/前进后退都停在该页（与现有四页同一套路由约定） |
| NFR-10 | 网络 | 账号级可选代理（`socks5://` / `socks4://` / `http://` / `https://`），用于国内直连被墙的信箱（主要是 Gmail）；不填 = 直连。代理地址随账号存本机库，不回传密码；未开代理时只影响该账号，其它信箱照常（见 D6） |

## 7. 界面要求

1. **入口**：侧栏新增一项「邮件」（图标用信封），排在便签/资产/观测/设置之间（位置见 Q6）。
2. **布局**：左右两栏——左列表（约 40%）、右阅读区（约 60%）；窄屏时可堆叠。
3. **顶部**：账号 chips（全部 / 各账号 + 未读数）、「数据截至 HH:MM:SS」、刷新按钮、搜索框、（P1）文件夹选择。
4. **列表行**：发件人 · 标题 · 摘要 · 时间（今天显示 `HH:mm`，更早显示 `MM-DD`）· 账号色点。
5. **空态**：没有账号时，展示「添加第一个邮箱」的引导卡片；有账号但无邮件时显示「收件箱是空的」。
6. **错误态**：某账号失败时，在该账号 chip 上标红点，鼠标悬停/点击显示具体错误。
7. **不使用弹窗打断阅读**；账号增删改用一个轻量抽屉/对话框。

## 8. 数据模型（概念层）

**mail_accounts**（新增表）

| 字段 | 说明 |
|---|---|
| id | 主键 |
| label | 显示名，如「Gmail 主号」 |
| email | 邮箱地址（用于展示） |
| host / port | IMAP 服务器与端口 |
| username | 登录名 |
| password | 授权码 / 应用专用密码（见 Q3） |
| security | `ssl` / `starttls` |
| enabled | 是否启用 |
| sort | 排序 |
| created_at / updated_at | 时间戳 |

**mail_local_read**（新增表，只存「我看过哪封」，不存任何邮件内容）

| 字段 | 说明 |
|---|---|
| account_id | 账号 id |
| folder | 文件夹，默认 `INBOX` |
| uid | 该邮件在服务器上的 UID |
| read_at | 本机记录时间 |

主键 `(account_id, folder, uid)`。**这是本机阅读痕迹，不是邮件内容**；邮件正文仍然只做内存缓存、不落库（见 Q4）。

## 9. 接口约定（概念层，供开发参考）

- `GET /api/mail/accounts` → 账号列表（**不含密码**）
- `POST /api/mail/accounts` / `PUT /api/mail/accounts/:id` / `DELETE /api/mail/accounts/:id`
- `POST /api/mail/accounts/test` → 试连，返回成功/失败原因
- `GET /api/mail/messages?account=all|<id>&folder=INBOX&limit=50&fresh=1` → 合并列表
- `GET /api/mail/message?account=<id>&folder=INBOX&uid=<uid>` → 单封正文（HTML + 纯文本）
- ~~`POST /api/mail/message/seen`~~ **不提供**：本页不修改服务器已读状态（D1）
- `POST /api/mail/local-read` → 记一条本地已读标记（只写本机 SQLite）
- `DELETE /api/mail/local-read` → 清除（单条或全部，见 FR-29）
- `GET /api/mail/folders?account=<id>` → 文件夹列表

5. 拔掉某个账号的授权码（或断网），其余账号照常显示，失败账号有明确错误提示。

## 13. 附录：已实测的技术事实（约束条件，写文档时已核实）

- 本机（Windows）**可直连** `imap.gmail.com:993`（实测 TLS 握手后返回 `* OK Gimap ready for requests from <你的公网出口 IP>`，597ms）；`imap.qq.com:993`（63ms）、`imap.163.com:993`（82ms）同样直连可达。**被墙的是 Gmail 网页 443 与发信端口 465/587，IMAP 993 不受影响。**
- 因此本需求**不需要**任何服务器、代理、Docker 或证书；数据通路是：浏览器 ↔ 本机 7788 ↔ 各邮箱 IMAP。
- 本机存在系统代理（`127.0.0.1:10808`，v2rayN + sing-box），可作为个别账号拉信异常时的备用通道（实测走代理同样能连上 Gmail IMAP）。
- 163 邮箱必须发送 IMAP ID 命令才能打开收件箱（Cypht 的 issue #2028 即此问题），实现时必须带上。
- Gmail 不接受网页登录密码，必须使用「应用专用密码」（需账号已开启两步验证）。
- ~~azfree 上 Cypht 的数据库（`cypht` 库）~~（该服务与数据库已于 2026-10-21 删除）实测只有 5 张表：`hm_login_attempts` / `hm_user` / `hm_user_session` / `hm_user_settings` / `migrations`，**没有任何邮箱账号记录**（当时 Gmail 就卡在 535 BadCredentials 没保存成功）。所以「已绑过的 Gmail」的授权码不在服务器上，验收时需用户重新提供一次。
- pinfolio现状：Node 24 + Hono + `node:sqlite` + React 19 + Vite，单进程单端口 7788，无鉴权，仅本机。
