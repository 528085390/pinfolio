# pinfolio 功能细节

两个最重的页面到底怎么用。概览见 [README](../README.zh.md)。

## 观测台
- 数据源是**本机的 Uptime Kuma**（默认 `http://127.0.0.1:3001`，状态页 slug `obs`），Kuma 只当探测后端，页面在 pinboard 里。
- **Kuma 自带的 `http://127.0.0.1:3001/status/obs` 已于 2026-10-19 下线**（返回 404），观测只看这一页。Kuma 的
  `/api/status-page/obs`、`/api/status-page/heartbeat/obs` 两个 JSON 接口保留，是这里的数据来源。
- 卡片一屏放完：4 列（≥1700px 宽屏 6 列），按机器分组排列（12 项时 2560×1440 两行、1600×900 三行；2026-10-20 加到 15 项 / 5 组后行数相应增加）。
- 每张卡片：名称 + 机器 + 类型、**最近 40 次心跳**的色条（绿=正常 / 红=故障 / 黄=待定 / 灰=维护）、响应毫秒、最近检查时间、24h 可用率、窗口内异常次数。**鼠标移到任意一段**就弹出这一拍的时间（精确到秒）、状态、相对时间、响应毫秒、「第 i/N 拍」与心跳消息，那一段还会稍微变大、把左右邻居挤开（移开回位）；抽屉里的色条同样能看。
- 顶部四格：观测项 / 正常 / 异常 / 24h 可用率；下面可按机器、状态筛选，或按名称 / 消息搜索。
- 默认 30 秒自动刷新（可关），也可以手动点刷新；卡片视图 / 表格视图切换。
- **跳转管理页**：有管理界面的观测项，标题后面带一个 ↗，点标题在新标签页打开对应项目的管理页（表格视图里同样可点）。映射写在根目录的 `monitor-links.json`，改完刷新页面即生效，不用重启。
  仓库里只带一份示例 `monitor-links.example.json`，**复制成 `monitor-links.json` 再改**（真文件已 gitignore，免得把自家面板地址提交上去）：

  ```json
  [
    { "id": 1, "name": "本地面板", "url": "http://127.0.0.1:7863/panel/", "label": "本地控制台" },
    { "id": 3, "name": "线上入口", "url": "https://example.com/panel/", "label": "线上控制台" }
  ]
  ```

  没配跳转的观测项（比如只探端口的 nginx / xray）就不显示 ↗。

  **按 `id` 匹配（优先）**：观测项可以在抽屉里改名，名字不是稳定键，所以规则以 `id` 为准，`name` 只当注释与兜底。
  换文件位置设 `MONITOR_LINKS` 环境变量。
- **点卡片（或表格行）打开右侧观测项详情抽屉**，和资产详情同一套交互：
  - **基本信息**：名称、介绍、检查频率（带 30 秒 / 1 分钟 / 5 分钟 / 10 分钟 / 30 分钟快捷键）；展开「高级设置」还能改超时、重试次数、重试间隔、是否常显消息。这些都**写回 Kuma**（Kuma 是唯一事实源，CLI 与 `SNAPSHOT.md` 看到的是同一份），保存后列表立即刷新。
  - **暂停 / 恢复观测**：暂停后卡片和表格行都变淡并标「已暂停」，Kuma 不再探测（历史心跳保留）；恢复即重新开始。
  - **删除观测**：抽屉里二次确认，**必须把观测项名字原样输一遍**按钮才可用；确认后先自动备份一份 `kuma/data/kuma.db` 到 `kuma/backups/kuma-YYYYMMDD-HHMMSS.db`（只留最近 5 份），再连同历史心跳一起从 Kuma 删除，不可撤销。
  - **立即观测**：不等下一个周期，立刻跑一遍这个观测项的「观测配方」，逐步骤回显耗时和结果。默认配方 = 让 Kuma 重启检查循环、马上真探一次；特殊观测项（比如每日打卡这种推送型、或要顺带刷新上游的）在根目录 `monitor-actions.json` 里按观测项 id 配多步配方，**改完不用重启**，刷新页面即生效。**#24 每日打卡已配好**：点按钮先确保 8765 面板在跑（没开就后台拉起），再 POST `/api/trigger-all`，详情里回显「一键出发已启动：N 个账号…」。
- 改名会同步到 Kuma；如果别的观测项的「策略」是按名字引用了它，改名会被拒绝并说明是谁引用了，避免策略静默失效。
- Kuma 挂了不会白屏：退回上一次数据并在顶部提示；连一次都没读到过，就显示「读不到观测项」+ 具体原因 + 重试按钮。
- **为什么分两半缓存**：Kuma 的 `/api/status-page/obs` 偶尔要 5–30 秒才回（它自己按 5 分钟缓存，缓存过期那一刻正好赶上 12 个探测在跑就会很慢），而心跳接口只要几十毫秒。所以后端把「观测项清单」缓存 5 分钟（启动时预热、每 5 分钟续一次）、心跳按需现取，页面正常 0.1–0.4 秒出全部卡片。

## 邮件（只读合并收件箱）
- 自己填 IMAP 服务器（Gmail / QQ / 163 / 任意 IMAP），**多个信箱合成一个收件箱**，按时间倒序；顶部的账号 chip 可只看某一个信箱，chip 上带未读数。
- **只收信，不改变服务器上的任何状态**：只用 `SELECT` / `SEARCH` / `FETCH(BODY.PEEK[])`，一行 `STORE` 都没有——打开邮件**不会**把服务器上的未读变成已读（客户端库 imapflow 的 `fetch` 天生就用 `BODY.PEEK`）。
- **已读只记在本机**：点开一封邮件，这一行变淡，标记存在本地库 `mail_local_read` 里，绝不写回服务器。设置抽屉里可以「清除本地已读标记」。
- 列表行：发件人、主题、1–2 行纯文本摘要、时间、所属信箱；未读加粗、已读淡化，账号筛选 chip 带未读数。**分页 50 封 / 页**，翻到最后一页为止（不会只显示最近一批）。
- 右侧阅读区不跳页：主题 / 发件人（名字 + 地址）/ 收件人 / 抄送 / 时间 / 信箱，正文 HTML 与纯文本一键切换。
- **排版**：邮件正文渲染在 **Shadow DOM** 里，邮件自带的 `<style>` 与内联 `style` 原样保留（只在邮件区域内生效，不会污染主界面），营销邮件的表格/多栏排版基本保持原样；固定宽度（如 720px）的邮件会等比缩小以适应阅读区，不会被裁掉。
- **安全**：正文仍经 DOMPurify 兜底清洗（去掉 script/iframe/form 等，剥掉 `@import`/`expression()`/`javascript:`/`position:fixed`），链接一律新标签页打开；`cid:` 内嵌图走本地附件接口。
- **图片**：**远程图片默认加载**（这样排版与配图才是原样）。不想给发件人追踪信号时，点阅读区顶部「隐藏图片」即可切到虚线占位，隐藏后正文顶部会提示「已拦截 N 张外部图片」并可一键恢复，选择记在本机浏览器里。⚠️ 加载远程图片**不会**改邮箱里的已读状态（本页永不回写服务器），但会给发件人一个「这封被打开过」的追踪信号。
- 附件只列清单 + 下载，不落库；超过 25 MB 的邮件不下载正文，直接提示。
- 搜索框在当前已加载的 50 封里做客户端筛选（发件人 / 主题 / 摘要），另有「只看未读」；`j` / `k` 上下选邮件。
- **自动收信**：页面开着时每 60 秒静默回源一次（只更新列表和未读数，不动你正在读的正文），切到别的标签页就暂停、切回来立刻补一次；工具栏的「数据截至 11:05:03」是这批数据真正从邮箱服务器取回的时刻。想立刻看新的就点「刷新」（绕过缓存）。
- 缓存：列表 60 秒、正文 10 分钟（只在内存里，不写磁盘），手动点「刷新」或自动轮询时绕过缓存并重新取未读数。
- 账号连接失败不会拖垮整页：那个信箱的 chip 上会出现红色感叹号，鼠标悬停看原因；其它信箱照常显示。
- 163 需要客户端发 `IMAP ID`（否则报 `Unsafe Login`），imapflow 登录时自动发，不用管；Gmail 要「应用专用密码」，QQ / 163 要「授权码」，填登录密码一定失败。
- **代理（Gmail 必备）**：国内直连 `imap.gmail.com:993` 经常被墙（表现为「连接超时」），账号抽屉里有个**「代理（可选）」**字段，填本机 SOCKS5 代理即可，如 `socks5://127.0.0.1:10808`（只写 `127.0.0.1:10808` 会自动补 `socks5://`）。也支持 `http(s)://` / `socks4://`；QQ / 163 留空直连。整库兜底可以设环境变量 `PINBOARD_MAIL_PROXY`（账号没填时生效）。
## 主机指标

「主机」页展示 6 台服务器的资源与状态。**数据不是实时探测，而是每台机自己每 5 分钟推一份快照**，所以「N 分钟前」是数据的新鲜度，不是页面在算。

- **链路**：服务器上的 `node-metrics.timer`（oneshot，跑 0.1–0.3 秒就退）→ `PUT https://203.0.113.10/metrics-ingest/<token>/<host>.json` → my-server 的 nginx 用 `dav_methods PUT` 直接落 `/var/www/metrics/`（**不新增进程 / 端口 / 后端**）→ 本机 pinfolio 每 5 分钟拉 6 个 JSON → SQLite 的 `host_metrics`。
- **采集字段**：CPU（`/proc/stat` 两次采样、1 秒窗口的 `Δtotal / Δidle`）、内存与 swap、load 三个值、uptime、每个挂载点的总量 / 已用 / 百分比、`failed_units` 计数、`WATCH_UNITS` 里每个服务的 `is-active`、内存占用前三的进程（只取 `comm`，不含参数）。
- **在线 / 陈旧**：最近一次样本在 5 分钟内 → 正常显示「N 分钟前」；超过 900 秒（3 个采集周期）算**陈旧**，卡片变灰、副标题写「N 台陈旧」。页面开着时 60 秒轮询一次（只读本机库，不打服务器）。
- **曲线**：24 小时的 CPU（橙）与内存（灰）两条线，`[ts, cpuPct, memPct]` 一天最多 288 个点。样本不足 2 个时写「还没有曲线」——**不画假线**。
- **手动拉取**：工具条的「立即拉取」走 `POST /api/hosts/refresh`，绕过 4 分钟最小间隔；日常页面刷新只会触发一次「最多每 4 分钟」的拉取，免得把 my-server 打穿。
- **时间戳不同步是正常的**：timer 带 `RandomizedDelaySec=20s` + `AccuracySec=30s`，6 台故意错峰。看到有的卡 2 分钟前、有的 5 分钟前，不是采集坏了。
- **点服务 chip 跳观测台**：卡片「服务」区里，凡是 `host-services.json` 配到了观测项的 chip 都可点（右边带一个 ↗ 小箭头），点了切到观测页、滚到那张卡并高亮 1.6 秒（不开详情抽屉）。没配到映射的仍是纯文字 chip，`title` 会说明没有对应观测项。映射表在仓库根 `host-services.json`：`host` + `unit` 定位采集端的服务名，`match` 在**该主机分组内**的观测项短名里做不区分大小写的包含匹配（也可用 `monitor` 直接钉 id）。观测项被删/改名后 chip 自动退回纯文字，不用改代码。
- **添加 / 暂停 / 删除**：工具条的「+ 添加主机」分三段 —— 基本信息（`id` 限字母数字 `.` `_` `-`、1–32 位、不能重名；显示名留空就用 id；`note` 只写机房）、采集端（服务清单 `WATCH_UNITS`、磁盘路径、地址）、观测项（端口 / HTTP 站点 / systemd 服务，默认都不勾）。保存后**直接弹出「接入这台机器」**：一条 `curl … && sudo bash …` 命令（复制即用）+ 「立即检查」，装完 timer 立刻上报第一帧，状态从「还在等第一帧」变「已收到首帧」。勾了观测项时会在观测台顺带建同名分组与观测项（命名 `<组短名> / <服务名>`，并把 id 记进 `data/metrics.json` 的 `monitors`），**建失败不影响主机**——错误会显示在页面上，主机照样收指标。卡片右上角 hover 出两个按钮：**暂停采集**（`paused`，卡片虚线变灰、副标题算「N 台暂停」、既不算离线也不算陈旧，历史曲线保留；要彻底停掉服务器上的上报得去那台机 `systemctl disable --now node-metrics.timer`，恢复后只能补到最新一帧）/ **删除**（弹窗里手输 id 才可点，默认同时删掉这台机 30 天历史样本、加主机时顺带建的观测项与空出来的分组）。
- **为什么不直接上 node_exporter + Prometheus + Grafana**：每台要常驻 15–25 MB，本机再加约 200 MB；oj 只有 945 MB（历史上装 dnf-automatic 把它拖死过）。现在服务器侧**零常驻**，磁盘 2 KB。
- **加一台机**：① 主机页点「+ 添加主机」填 id / 服务清单 / 磁盘 / 地址，要监控端口或站点就顺手勾上；② 保存后复制弹窗里那条命令，到目标机 `sudo` 跑一遍（下载单文件安装器 → 写 `/etc/node-metrics.conf` → 装 timer → 立刻上报一帧）；③ 弹窗里点「立即检查」或等 5 分钟，卡片从「还没收到上报」变成正常指标。没有界面时也能手装：`curl -fsSL https://203.0.113.10/nm/node-metrics-install.sh | sudo bash -s -- <URL> <HOST_ID> "<WATCH_UNITS>" "<DISK_PATHS>"`。
- **排错**：`systemctl status node-metrics.service`（应 `status=0/SUCCESS`）→ `node-metrics.sh --print`（只打印不上报）→ `curl https://203.0.113.10/metrics/<token>/<id>.json`（看落盘那份）→ 本机 `GET /api/hosts` 看 `pollOk` / `pollFailed`。
